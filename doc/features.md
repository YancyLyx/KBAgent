## 核心功能

### 1. 多格式文档接入
- **PDF**：字号分析检测章节（1.3 倍正文为子标题，1.8 倍为章标题）+ pdfplumber 提取表格。图片标题从邻近文本提取，不依赖 OCR。
- **Markdown**：按 #/##/### 标题层级分块。识别代码块和表格。
- **纯文本**：RecursiveCharacterSplitter 兜底分块。

为什么：企业知识库的现实是 PDF/MD/TXT 混存，解析质量直接决定分块质量——
解析丢内容，后面检索再好也救不回来（test-corpus 答案保留率 97% 就是验证手段）。

### 2. 父子分块策略
文档经过两级分块管线：先按章节语义切分为父块（`chunk_size=1000`），再进一步切分为子块（`child_chunk_size=300`）。子块用于精确匹配检索，父块作为 LLM 上下文保证信息完整。

为什么：单层大块召回精度被稀释，单层小块上下文断裂；父子方案"子块保精度、
父块保完整性"，代价是多一层索引和去重逻辑（详见 hybrid_retrieval.md）。

### 3. 混合检索（RRF + 重排序）
双引擎检索：向量相似度（bge-small-zh）+ 关键词匹配（BM25）。通过 Reciprocal Rank Fusion 合并结果，再经 bge-reranker-base CrossEncoder 精排。

为什么：向量管语义、BM25 管精确词，两路信号互补；RRF 按排名融合而不是按分数
加权，因为两路分数分布不可比（详见 hybrid_retrieval.md）。

### 4. 渐进式多知识库路由（Skill 系统）
文档上传时通过自由文本标签分类，系统自动维护多知识库索引。LLM 渐进式发现：先看到分类概览，通过 read_category_info 了解详情，再调用 search_knowledge_base 检索。

为什么：多知识源混在一个向量池会互相污染召回；先让 LLM"选择去哪个图书馆"
再检索，用一次廉价调用收敛范围（详见 skill_system.md）。

### 5. ReAct Agent 架构
ReAct 循环（最多 5 轮）：LLM 自主推理决策，每轮可选择调用工具或直接回答，支持多步连续工具调用。支持 6 个工具：知识库检索（2 个）、文件操作（4 个）。

为什么：问题类型开放（单库/跨库/闲聊），Workflow 枚举不完；LLM 决策换来灵活性，
代价是输出不可控，所以循环外加了 6 层防御（白名单/三级解析/必填校验/隔离/
防循环/截断，详见 architecture.md 与 interview_prep.md）。

### 6. 多层记忆系统
- 短期记忆：deque 保留最近 N 轮（当前配置 10），保证对话连贯
- 长程对话记忆：ChromaDB 存储，支持跨会话语义召回
- 演进式摘要：每 N 轮（N=短期记忆窗口 max_history_length）LLM 自动更新，参考 Codex 压缩机制
- 用户画像：LLM 自动提取用户角色、偏好与关键事实

为什么：三层分别解决"近/中/远"记忆——滑动窗口管最近、摘要管压缩后的长期状态、
向量召回管"用户提起旧话题"的场景（详见 memory_system.md）。

### 7. LLM-as-Judge 评测系统
每次对话自动从相关性、完整性、有用性三维度评分。低分触发告警与兜底策略（扩大检索 + 重新生成）。配置更新保存基线用于回归对比。

为什么：没有标注数据也能实时评估主观质量；低分自动兜底形成闭环；
离线 67 条 QA 评测集负责"改检索策略后回归验证"（详见 evaluation.md）。

### 8. 管理仪表盘
实时统计：对话数、评测分数、告警监控、文档管理（标签式知识库组织）。

为什么：Agent 不能是黑盒——告警数量和评测趋势让"效果好不好"可观测，是线上
排查和面试讲"工程闭环"的依据。

## 生产加固（完善记录）

### 检索正确性
- BM25 中文分词改为重叠 bigram，修复「整句一个 token、关键词永远匹配不上」的问题
- BM25 支持 tag 过滤并携带 metadata，修复按知识库检索混入其他库、父子分块丢失父块上下文
- Advanced RAG 增强：超长结果 LLM 上下文压缩、复杂查询多查询分解 + HyDE 增强检索、MMR 去冗余、重排相关性阈值过滤
- Autocut 分数悬崖动态截断：重排后按最大相对落差截断，替代固定 TopK 的噪声注入（配置开关，默认关）
- Self-RAG 检索反思：检索后 LLM 判断充分性，不足改写查询补检（内容去重合并、无新增即停，配置开关，默认关）
- 文档删除/重索引同步清理向量分块并重建 BM25 索引，修复「文件已删仍被检索」

### 缓存
- 缓存键加入 user_id namespace，修复跨用户串答案
- TTL（1 小时）+ 文档变更主动失效，修复知识库更新后旧答案命中
- 进程级共享缓存，修复每个会话一个空缓存、命中率趋近于 0
- 缓存命中同步更新短期记忆，修复命中后追问上下文断裂

### Agent 循环
- 工具名白名单校验（幻觉工具名回填错误）、必填参数校验（不再生成 None.md）
- LLM 调用增加超时与 SDK 重试；错误显式返回 success=false + error
- 低分兜底复用已有 RAGPipeline 与首轮检索结果，兜底答案不写缓存
- Loop Engineering：轮数/预算/各阶段 max_tokens 统一配置化（loop_config.yaml），
  工具结果上限按「窗口−上下文−预留−余量」动态计算
- 无进展检测：结果签名连续相同提示停止（防"换参数但结果一样"），与指纹防循环互补

### 兜底策略（四层）
- 诚实原则写进 system prompt：检索不到明确告知、不编造；通用常识可答但标注来源
- strict/lenient 场景标签：制度类（薪酬/股权/报销/福利等）严格拒绝编造，宽松场景允许通用知识兜底但标注
- 检索空结果挽回：放大召回附低相关候选（"仅供参考"）+ 引导换关键词/补充细节话术
- 失败 query 日志闭环：missed_queries.jsonl 记录 → 高频聚合 → 管理端 /api/admin/eval/missed

### 记忆
- 演进式摘要触发时机与短期记忆窗口对齐（修复原实现永远不触发的缺陷）
- 对话记忆 turn_index 进程重启后自动恢复 + doc_id 唯一化（修复重启后 500）
- 用户偏好 JSONL 文件存储（只追加、保留完整时间线），LLM 综合判断矛盾并主动澄清
- 用户可对偏好增删改查（/api/profile/preferences），文件即历史、天然可审计
- 演进式摘要只保留最近 N 行（keep_recent 可配），历史靠 Chroma 快照兜底
- 注入路由：纯闲聊跳过画像/摘要注入（省 token）
- 管理端记忆纠错 API：查看画像/摘要/审计日志、删除单条偏好、一键清空记忆
- 查询改写：指代问题（"那个方案"）先 LLM 补全实体再检索，失败回退原查询

### 生产稳定性
- 活跃会话空闲超时回收 + 数量上限（修复内存泄漏）
- /chat 全链路异步化：LLM 调用换 AsyncOpenAI（非阻塞），embedding/rerank 线程池化
